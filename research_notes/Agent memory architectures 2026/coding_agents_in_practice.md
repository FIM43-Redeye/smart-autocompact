# Coding agents in practice: memory, context management, and retrieval (state as of 2026-11-11)

Method note: all sources below were downloaded and read this session (vendor docs/blogs = primary). Items marked [snippet-only] come from search snippets/secondary write-ups and are unverified. Windsurf/Devin memories, Goose, and Claude Code "session memory" as a named feature: no usable primary source obtained (see Gaps).

## Q1. Claude Code: CLAUDE.md, auto memory, compaction, what survives

### Takeaway
Claude Code keeps durable state on disk and re-injects it after compaction: CLAUDE.md, the auto-memory index, plan-mode plan, up to 5 recently read files, invoked skill bodies, SessionStart(compact) hook output. Conversation-only instructions, hook-added context, and path-scoped rules/nested CLAUDE.md are summarized away unless re-triggered. Topic memory files are never auto-loaded: only the MEMORY.md index is, so the pointer-plus-on-demand-read pattern is already the native design.

### Cited Findings
- Auto memory: "Each project gets its own memory directory at `~/.claude/projects/<project>/memory/`"; derived from the git repo so all worktrees share it; machine-local, not shared across machines. Layout: `MEMORY.md` "Index, one line per memory, loaded into every session" plus one topic file per memory. — [memory docs](https://code.claude.com/docs/en/memory.md)
- Load limit: "The first 200 lines of `MEMORY.md`, or the first 25KB, whichever comes first, are loaded at the start of every conversation." Beyond that is not loaded. "Claude Code doesn't load topic files such as `user_role.md` ... at startup. Claude reads them on demand using its standard file tools." The limit applies only to MEMORY.md; CLAUDE.md loads whole (skipped if >4 MiB). — [memory docs](https://code.claude.com/docs/en/memory.md)
- After Claude writes MEMORY.md, Claude Code measures it against the 200-line/25KB limits; near limit it reminds Claude to "keep one line per entry, move detail into topic files, and merge or drop stale entries"; over limit the write succeeds but an error tells Claude to rewrite the index. — [memory docs](https://code.claude.com/docs/en/memory.md)
- Who writes: Claude itself, during the session ("Saved 2 memories"/"Recalled 2 memories" UI messages); no separate writer agent is documented. Four typed notes via frontmatter `type`: user, feedback, project, reference. "Claude skips anything it can derive from the codebase, such as architecture, file paths, or debugging fixes", and anything CLAUDE.md already says. "Claude doesn't save something every session." On write with YAML frontmatter, Claude Code stamps a `modified` ISO 8601 timestamp "to show how current the fact is, both to you and to Claude". On by default locally; off via `autoMemoryEnabled` / `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`; relocatable via `autoMemoryDirectory`. Memory files are excluded from the transcript retention sweep (`cleanupPeriodDays`). Subagents don't get the main auto memory (forks do); subagents can have their own memory dir. — [memory docs](https://code.claude.com/docs/en/memory.md)
- CLAUDE.md guidance: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." `@imports` "don't reduce its context cost". Path-scoped `.claude/rules/*.md` load only when matching files are touched. — [memory docs](https://code.claude.com/docs/en/memory.md)
- What survives compaction (table): system prompt/output style still apply; project-root CLAUDE.md and unscoped rules "Re-injected from disk"; auto memory "Re-injected from disk"; skill descriptions rebuilt (v2.1.304+); fresh git status; plan-mode plan re-injected from disk; `paths:` rules and nested CLAUDE.md "reload on demand"; "Files Claude read or edited: re-reads up to five, most recently modified first" (a file >5,000 tokens returns as a path reference, shown as `Referenced file`); invoked skill bodies re-injected, "capped at 5,000 tokens per skill and 25,000 tokens total; oldest dropped first", truncation keeps the start of the file; background tasks keep running; "Context that hooks added earlier: Summarized with the rest"; "SessionStart hooks that match the `compact` source: Claude Code runs them and adds their output to the compacted context". — [context-window docs](https://code.claude.com/docs/en/context-window.md#what-survives-compaction)
- Path-scoped rules/nested CLAUDE.md "load into message history ... so compaction summarizes them away"; docs advise dropping `paths:` or moving to root CLAUDE.md if it must persist. — [context-window docs](https://code.claude.com/docs/en/context-window.md)
- Docs state the summary "keeps your requests and key code snippets, but detailed instructions from early in the conversation may be lost. Put persistent rules in CLAUDE.md". Control via a "Compact Instructions" section in CLAUDE.md or `/compact focus on ...`. Also `/rewind` -> "Summarize from here/up to here". — [how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works.md)
- Thrash guard: if a single file/tool output refills context after each summary, "Claude Code stops auto-compacting after a few attempts and shows an error instead of looping". — [how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works.md)
- Thresholds: native-1M models (Fable, Sonnet 5+, Haiku 5.5, Opus 4.7+) compact "at about 967K tokens by default"; Sonnet/Opus 4.6 without extended context compact at the 200K boundary; `/autocompact 500k` / `autoCompactWindow` sets earlier trigger. — [model-config](https://code.claude.com/docs/en/model-config.md#default-auto-compact-thresholds)
- Idle compaction (on by default, v2.1.302+): compacts a conversation after about an hour idle when context has reached threshold (default 200,000 tokens), prompt cache is on the 1-hour TTL, and auto-compact is enabled; notice reads "Compacted while idle, before the prompt cache expired". Rationale implied: next message sends a summary instead of the whole (cache-expired) conversation. Disable with `idleCompaction: false`. — [settings-reference](https://code.claude.com/docs/en/settings-reference.md)
- Cost guidance: move workflow-specific instructions from CLAUDE.md to skills since skills load on demand. — [costs](https://code.claude.com/docs/en/costs.md)
- Skills listing: every skill name always in listing; with many skills, descriptions are dropped to fit a character budget; `description`+`when_to_use` truncated at 1,536 chars, "Put the key use case first". — [skills docs](https://code.claude.com/docs/en/skills.md)

### Inferences
- The plugin's "pinned constraint list re-injected after each compaction" duplicates what a SessionStart hook with `compact` matcher can do natively, and CLAUDE.md/MEMORY.md already reload; the unique gap is conversation-only constraints and post-compaction file pointers (native re-read is capped at 5 files/5,000 tokens each).
- The 200-line/25KB MEMORY.md cap is a hard budget for any index of pointers; Claude Code itself nudges toward "one line per entry".

### Gaps
- No documented "session memory" feature name found in the docs I read (grep of the downloaded pages returned only an Anthropic cookbook recipe link on "session memory compaction"). The exact summarizer prompt for auto-compact was not read.

## Q2. Anthropic API / platform and engineering posts

### Takeaway
Anthropic's position (2025-26): compaction alone is insufficient for multi-window work; pair it with files (progress file, JSON feature/test list, git) and just-in-time retrieval; use tool-result clearing as the lightest compaction; let strong models decide what to remember; resets can beat compaction for models with "context anxiety" but that behavior vanished with Opus 4.5+.

### Cited Findings
- Memory tool `memory_20250818`, client-side: Claude issues file commands (view, create, str_replace, insert, delete, rename) against `/memories`; "Claude automatically checks its memory directory before starting a task". Stable; supported on Sonnet 4.5 through the current Opus/Sonnet/Haiku 5.x list. Described as "just-in-time context retrieval... records what it learns in memory files and reads them back on demand." — [memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool.md)
- Context editing (beta header `context-management-2025-06-27`): `clear_tool_uses_20250919` clears oldest tool results chronologically, replaced by placeholder text; options `trigger` (input_tokens), `keep` (tool_uses), `clear_at_least`, `exclude_tools`, `clear_tool_inputs` (default false). `clear_thinking_20251015` clears older thinking blocks, `keep` default `{thinking_turns: 1}` when included without `keep`. Tool clearing invalidates the cached prefix, hence `clear_at_least`. With the memory tool: "Claude receives an automatic warning to preserve important information" as the clearing threshold nears. — [context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing.md)
- Reported numbers (internal agentic-search eval, vendor claim): memory tool + context editing "improved performance by 39% over baseline"; context editing alone 29%; in a 100-turn web search eval context editing cut token consumption by 84% and let workflows finish that would otherwise fail from context exhaustion. — [Anthropic, context management post](https://claude.com/resources/articles/context-management) (read via downloaded copy an_context_mgmt)
- Server-side compaction: `compact_20260112` edit, trigger default `{"type":"input_tokens","value":150000}`, minimum 50,000; `pause_after_compaction` (default false) stops after the summary so you can re-insert recent messages or instruction messages; `instructions` "Completely replaces the default prompt". Default summary goes in `<summary>` tags. A newer on-demand variant (beta header `compact-2026-09-04`, `compaction: {type: "summarize"}`) returns a signed compaction block with `stop_reason: "compaction"`; it can keep recent turns word for word, run in the background, and re-compact (new block summarizes old summary). Docs: "Use on-demand compaction wherever it is available." — [compaction overview](https://platform.claude.com/docs/en/build-with-claude/compaction), [threshold page](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold), [on-demand](https://platform.claude.com/docs/en/build-with-claude/compaction-on-demand)
- Effective context engineering (Sept 2025): agents keep "lightweight identifiers (file paths, stored queries, web links, etc.)" and load data at runtime; Claude Code is a hybrid: "CLAUDE.md files are naively dropped into context up front, while primitives like glob and grep allow it to navigate its environment just-in-time". Compaction "the first lever"; "overly aggressive compaction can result in the loss of subtle but critical context"; tuning advice: maximize recall first, then trim. Tool-result clearing "one of the safest lightest touch forms". Structured note-taking (NOTES.md, to-do) gives "persistent memory with minimal overhead". Also: "do the simplest thing that works". — [Anthropic engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)
- Effective harnesses for long-running agents: "compaction isn't sufficient". Failures: one-shotting the app and running out mid-feature; later session declares the job done. Fix: initializer agent creates `init.sh`, `claude-progress.txt`, initial git commit, and a JSON feature list with a `passes` field; each coding session reads progress file + `git log`, runs a basic e2e test, does one feature, commits, updates progress. JSON chosen "as the model is less likely to inappropriately change or overwrite JSON files compared to Markdown"; strongly worded rule "It is unacceptable to remove or edit tests". — [Anthropic engineering](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)
- Harness design for long-running apps (2026-03-23): context resets (clear window + structured handoff) vs compaction: compaction "doesn't give the agent a clean slate, which means context anxiety can still persist"; Sonnet 4.5 showed context anxiety, "Opus 4.5 largely removed that behavior"; with Opus 4.6 sprints were removed and the builder "ran coherently for over two hours". — [Anthropic engineering](https://www.anthropic.com/research/harness-design-long-running-apps)
- Managed Agents: "The session is not Claude's context window". Compaction/memory/trimming "all involve irreversible decisions about what to keep"; session event log is durable and the harness can re-read positional slices (`getEvents()`). Harness assumptions go stale as models improve (resets became "dead weight"). — [Anthropic engineering](https://www.anthropic.com/research/managed-agents)
- Long-running Claude for scientific computing: `CHANGELOG.md` as "portable long-term memory"; record "failed approaches and why they didn't work"; commit after each unit of work; test oracle. — [Anthropic](https://www.anthropic.com/research/long-running-claude) (downloaded copy an_long_running_claude)
- The components of agent memory (2026-11-06, newest): memory = notes saved between sessions, excluding compaction. Claude Sonnet 3.7 wrote 413 memory files across 225 folders in Pokemon and got 1 badge; Fable 5 wrote nine files plus a `global.md` dashboard and got 4; Sonnet 3.7's detailed records went stale and it spent time "combing through its memories". "For stronger models, giving them freedom to judge salience was more effective than setting fixed rules" ("record only failures" cut gains). Telling Claude to read memory before answering "nearly doubled" Sonnet 4.6's CL-Bench score; Sonnet 5 read memory first 9/10 times vs under half for Sonnet 4.6. "Dreaming" (offline reflection over logs/transcripts) corrects wrong notes and builds wiki-style linked pages: over 128 sessions on a ~350,000-file, ~420M-token corpus, 25-question score rose 13% to 48%; wiki+search 54% to 61%; merger Q&A 87% with wiki vs 73% search alone. Memory is "a prediction about what the future will need". — [Anthropic engineering](https://www.anthropic.com/research/components-of-agent-memory)
- Skills: name+description of every skill preloaded in system prompt (first level of progressive disclosure), SKILL.md body loaded when judged relevant, further files on demand. Authoring: description says what it does and when to use it, third person, specific key terms; body under 500 lines; reference files one level deep. — [Anthropic engineering](https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills), [skill best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)

### Inferences
- Anthropic's own evidence favors small, curated, current-state memory with model-judged salience over exhaustive logs; a stale-prone 400-file memory is the documented failure mode.
- The plugin's design (summary + pinned constraints + path pointers) matches "restorable compression" and the harness-post recipe, but the harness post suggests adding a machine-checkable status file (JSON, `passes` flags) rather than prose for constraints that must not be edited.

### Gaps
- Anthropic's evaluation numbers for "39%/29%/84%" are an internal vendor eval with no public methodology. No 2026 post quantifying compaction vs reset in Claude Code specifically was found.

## Q3. OpenAI Codex

### Takeaway
Codex: opaque encrypted server-side compaction, AGENTS.md read in full up to a byte cap, and (2026) an optional, off-by-default background-generated local memory store that OpenAI itself says not to rely on for must-follow rules.

### Cited Findings
- Compaction: enable via Responses `context_management` with `compact_threshold`; when rendered tokens cross it the server compacts, and "The response stream includes the encrypted compaction item"; the item "is opaque and not intended to be" inspected; you may drop items before the latest compaction item. ZDR-friendly with `store=false`. Standalone `/responses/compact` also exists. — [OpenAI compaction guide](https://developers.openai.com/api/docs/guides/compaction)
- Codex prompting guide (GPT-5.1-Codex-Max era): "Compaction enables multi-hour reasoning without hitting context limits". — [Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)
- AGENTS.md: global `~/.codex/AGENTS.override.md` or `AGENTS.md`; then root-to-cwd walk, one file per directory, concatenated root-down so nearer files override; stops at `project_doc_max_bytes` (32 KiB default). — [Codex AGENTS.md docs](https://learn.chatgpt.com/docs/customization/agents-md)
- Memories: local Codex memories "off by default"; background generation from eligible prior chats, skipping active/short-lived sessions, waits for idle, redacts secrets, may skip when rate-limit remaining is below a threshold; stored under `$CODEX_HOME/memories_v2/` (or legacy `memories/`) with "generated summaries and supporting evidence"; config keys `memories.generate_memories`, `use_memories`, `extract_model`, `consolidation_model`, `disable_on_external_context`. Explicit guidance: "Keep required team guidance in `AGENTS.md`... Treat memories as a helpful recall layer, not as the only source for rules that must always apply." — [Codex memories docs](https://learn.chatgpt.com/docs/customization/memories)
- Factory's eval (third party, vendor-run) calls OpenAI's compact endpoint opaque with 99.3% compression and lowest accuracy of three (see Q4). 

### Gaps
- Nothing found from OpenAI measuring long-horizon degradation attributable to compaction, nor how Codex retrieves memories (injection vs search), beyond the config key names.

## Q4. Other agents and platforms

### Takeaway
Convergence: file/path-based externalization (Manus, Cursor, Cognition) plus lossy summaries with a recovery path to the original. Dissent: Amp tried "handoff" instead of compaction and reversed in May 2026; Factory shows summary structure and incremental merging matter more than compression ratio.

### Cited Findings
- Manus (2025-07-18, Yichao Ji): "treat the file system as the ultimate context... unlimited in size, persistent by nature, and directly operable by the agent"; "Our compression strategies are always designed to be restorable": drop page content if URL kept, drop document content if path kept; "any irreversible compression carries risk"; todo.md recitation "pushes the global plan into the model's recent attention span"; "leave the wrong turns in the context"; KV-cache hit rate "single most important metric", ~100:1 input:output, 10x cached/uncached price (0.30 vs 3 USD/MTok); append-only context, mask tools via logits instead of removing. — [Manus blog](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Cursor dynamic context discovery (2026-01-06): long tool outputs become files; on summarization "we give the agent a reference to the history file" it can search to recover what the lossy summary dropped; MCP tool descriptions synced to a folder, A/B: "reduced total agent tokens by 46.9%" in runs that called an MCP tool; skills standard supported. — [Cursor blog](https://cursor.com/blog/dynamic-context-discovery)
- Amp: removed compaction for Handoff (2025-10-23), reasoning compaction "encourages long, meandering threads, in which you just compact once you run out of context window, stacking summary on top of summary"; handoff drafts a new-thread prompt plus relevant files. Reversed in "Amp, Rebuilt" (page dated 2026-05; Amp Neo): auto-compaction at 90% full; "So handoff is out. Compaction is in."; "Today's leading frontier models are great at handling compaction"; a user: "NOT missing handoff". — [Amp handoff](https://ampcode.com/news/handoff), [Amp Neo/rebuilt](https://ampcode.com/news/neo)
- Factory (2025-12-16), probe-based eval (recall/artifact/continuation/decision; vendor-run, statistical test not detailed): overall Factory 3.70, Anthropic 3.44, OpenAI 3.35 (of 5); artifact trail weak for all (2.45/2.33/2.19). Factory's "anchored iterative summarization" merges only the newly truncated span into a persistent structured summary (sections: intent, file modifications, decisions, next steps); Anthropic regenerates the full summary each time. "Compression ratio turned out to be the wrong metric... What matters is total tokens to complete a task." — [Factory](https://factory.com/news/evaluating-compression)
- Cognition/Devin (2025-09-29, Sonnet 4.5): model "treats the file system as its memory without prompting" (CHANGELOG.md, SUMMARY.md, not CLAUDE.md/AGENTS.md) but "the summaries weren't comprehensive enough... the model didn't know what it didn't know"; model-written notes were "less effective than our existing memory systems"; context anxiety "can actually hurt performance"; keep own compaction. Earlier (2025-06-12): "share full agent traces, not just individual messages". — [Cognition Sonnet 4.5](https://cognition.com/blog/devin-sonnet-4-5-lessons-and-challenges), [Don't build multi-agents](https://cognition.com/blog/dont-build-multi-agents)
- Cline Memory Bank: convention, not a feature: custom instructions in `.clinerules/` tell Cline to maintain `projectbrief.md`, `productContext.md`, `systemPatterns.md`, `techContext.md`, `activeContext.md`, `progress.md`; user asks it to "initialize memory bank"; Cline reads them at task start per the rule. — [Cline docs](https://docs.cline.bot/features/memory-bank)
- Roo Code: "Intelligent Context Condensing" on by default, LLM summarization at a configurable threshold (default 100% of window), custom condensing prompt; slash commands in first message preserved. — [Roo docs](https://roocodeinc.github.io/Roo-Code/features/intelligent-context-condensing)
- OpenCode: config `compaction: {auto: true, keep: {tokens: 15000}, buffer: "15%"}`; local summaries default, optional native provider compaction (the config text names a model I could not verify). — [OpenCode config](https://opencode.ai/docs/config/)
- Gemini CLI: hierarchical `GEMINI.md` context files (home, workspace, subdirectory), `/memory show/refresh/add`. — [Gemini CLI docs](https://geminicli.com/docs/cli/gemini-md)
- GitHub Copilot Memory: repo-level facts with citations to code, checked against the current branch when used ("a judgment Copilot makes, rather than a guarantee"); user-level preferences; created by Copilot, not hand-editable ("You cannot directly create or edit an individual memory"); automatic up/down-voting, downvoted memories stop being used and are deleted after disuse; not all memories sent with a prompt. — [GitHub docs](https://docs.github.com/en/copilot/concepts/agents/copilot-memory)

### Inferences
- Staleness defenses seen in production: timestamps (Claude Code), citation re-verification (Copilot), vote-based decay (Copilot), dreaming/transcript audit (Anthropic), explicit "derivable facts excluded" rules (Claude Code).

### Gaps
- Windsurf Memories/Devin knowledge, Goose, Jules: pages I fetched were unusable (SPA shell/404); no claims made. Cursor's current Memories/rules pages returned 404 at the guessed URLs.

## Q5. Retrieval: agentic search vs embeddings vs graphs

### Takeaway
Evidence is mixed and scale-dependent. Claude Code/Cline/Letta/Cognition favor grep-style agentic search (simple, fresh, no index); Cursor reports measured gains from adding embeddings on large repos. Independent measurement exists but mostly outside coding (LongMemEval) or via secondary reports.

### Cited Findings
- Claude Code lead Boris Cherny (Latent Space, May 2025): early versions "used RAG... I think we were just using Voyage"; they landed on agentic search: "it outperformed everything. By a lot... This was just vibes, so internal vibes. There's some internal benchmarks also"; plus the index "drifts out of sync", security liability of hosting the index; "at the cost of latency and tokens, you now have really awesome search". Vendor claim, no published numbers. — [Latent Space transcript](https://www.latent.space/p/claude-code)
- Cursor (Nov 2025 post, date inferred): own embedding model; "on average 12.5% higher accuracy" (6.5%-23.5% by model) with semantic search + grep vs grep alone; A/B: code retention +0.3%, "2.6% on large codebases with 1,000 files or more". Vendor-run. — [Cursor semantic search](https://cursor.com/blog/semsearch)
- Cognition/Windsurf SWE-grep (2025-10-16): embeddings "can even be counterproductive, as the agent can give too much weight to irrelevant information"; plain agentic search is slow (dozens of roundtrips) and "context poisoning"; their answer is an RL-trained subagent (8 parallel tool calls, 4 serial turns, returns file+line ranges not summaries); >60% of first-turn time was retrieval. Neither pure approach. — [Cognition SWE-grep](https://cognition.com/blog/swe-grep)
- Letta (2025-08-12): plain files + grep/search tools scored 74.0% on LoCoMo (gpt-4o-mini) vs Mem0's reported 68.5% for its top graph variant; "simpler tools are more likely to be in the training data"; "more complex solutions like knowledge graphs... may come at the cost of being more difficult for the LLM to understand". Note Letta's files were also embedded and a semantic search_files tool was available, so it is not grep-only. Vendor with a competing product. — [Letta](https://www.letta.com/blog/benchmarking-ai-agent-memory/)
- Independent paper: "Is Grep All You Need? How Agent Harnesses Reshape Agentic Search" (arXiv 2605.15184, 14 May 2026): 116 LongMemEval questions, harnesses Chronos plus Claude Code, Codex, Gemini CLI; "grep generally yields higher accuracy than vector retrieval", but scores "depend strongly on which harness and tool-calling style is used". Not a code benchmark. Abstract read; per-cell numbers not extracted. A secondary blog says vector can win when outputs must be read back from files [snippet-only]. — [arXiv](https://arxiv.org/abs/2605.15184)
- [Snippet-only, unverified] CORE-Bench (mid-2026) reportedly finds code embedding models don't close the gap with grep; Augment's SWE-bench write-up reportedly found grep/find sufficient. — search results only.
- Anthropic: "do the simplest thing that works"; hybrid (up-front CLAUDE.md + JIT exploration). Anthropic wiki experiment: linked wiki + search beat search alone (87% vs 73%; 54% to 61%), i.e. a curated index/map helps even over a searchable corpus. — sources in Q2.

### When pointers fail (documented)
- Model doesn't read memory: Sonnet 4.6 read memory under half the time; prompting nearly doubled score; Sonnet 5 reads 9/10. — [Anthropic components of memory](https://www.anthropic.com/research/components-of-agent-memory)
- Index too big/too many files: Sonnet 3.7's 413 files; Claude Code truncates MEMORY.md at 200 lines/25KB, silently dropping the tail from session start. — sources above
- Stale pointers/notes: wrong note ("Mt Moon DONE") trusted later; Copilot says its citation check is judgment, "not a guarantee".
- Skill description truncation when many skills (1,536-char cap, budget drops descriptions). — [skills docs](https://code.claude.com/docs/en/skills.md)
- Model-written notes incomplete ("didn't know what it didn't know") — Cognition.

### Inferences
- For a plugin with few dozen long-term docs, an index of path + one-line "when to read" is within current evidence; embeddings only pay off at large-corpus scale (Cursor's 1,000+ files signal) and add index-freshness cost. Put the pinned instruction "read X before doing Y" in the always-loaded layer, since models skip optional reads.

### Gaps
- No independent, code-specific, peer-reviewed measurement of memory-file pointer reliability. Knowledge-graph results for coding agents: nothing primary found.
